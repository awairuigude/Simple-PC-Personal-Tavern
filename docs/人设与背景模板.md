# 人设与背景模板

不要把所有资料塞进一段系统提示词。不同信息应放在对应层中，这样模型切换、长期记忆和世界书触发才容易维护。

## 角色卡：AI 扮演的人

### Name / 名称

角色的固定姓名。

### Description / 角色描述

```text
身份：
年龄：（涉及成人题材时明确为成年人）
外貌与稳定身体特征：
职业 / 能力 / 知识边界：
关键经历：
与用户及其他人物的初始关系：
不会轻易改变的事实：
```

### Personality / 性格摘要

```text
核心性格：
说话方式与口头习惯：
主要欲望：
恐惧与弱点：
底线：
面对亲密时：
面对冲突时：
面对压力时：
```

用可以在正文中观察到的行为描述性格，少用互相矛盾的形容词堆砌。

### Scenario / 场景

```text
时代与地点：
当前时间：
当前处境：
双方为什么在这里：
开局目标：
主要冲突：
尚未解决的事件：
```

Scenario 描述开局，不要把很久以后的剧情预先写成既定事实。

### First Message / 首条消息

直接写故事开场正文。它会同时决定最初的：

- 叙事人称和视角
- 对话与动作格式
- 句子长度和段落密度
- 角色主动程度
- 单次回复的大致篇幅

### Example Messages / 示例对话

准备 2-5 段最能体现角色语言、动作和叙事文风的示例。示例用于让模型模仿表达，不适合存放大量世界设定。

```text
<START>
{{user}}：示例中的用户消息。
{{char}}：符合目标文风的角色回复。
```

### System Prompt / Post-History Instructions

只放角色专属、且必须长期执行的规则。例如独特视角、特殊语言习惯或能力限制。通用叙事规则放在模型预设中，避免每张角色卡重复一遍。

## Persona：用户在故事中的身份

```text
姓名：
年龄：
外貌：
身份 / 职业：
能力与知识：
经历：
与角色的关系：
用户已经明确决定的长期偏好：
```

Persona 只描述稳定资料。不要预写用户下一步会说什么、做什么，也不要把尚未发生的剧情写成事实。

## 世界书：按条件出现的背景资料

适合放入世界书的内容：

- 地点
- 组织和制度
- 配角
- 物品
- 魔法、科技或力量体系
- 专有术语
- 只在特定场景需要的隐藏设定

每个条目尽量只写一个主题，并设置准确的触发关键词。

```text
条目名称：北站
触发词：北站, 站台, 候车厅
内容：地点布局、工作人员、规则、已知事件等稳定资料。
```

触发词过宽会让无关条目频繁占用上下文；过窄则会漏召回。当前剧情必须知道的事实，不应只依赖一个很难触发的关键词。

## 作者注释：当前阶段的短期方向

```text
本章目标：
气氛：
镜头重点：
节奏：
近期不能遗忘的限制：
```

剧情阶段结束后删除或改写作者注释，不要让旧目标长期污染后续剧情。

## 长期总结

累计总结建议包含：

```text
人物与关系：
按时间排序的关键事件：
当前时间与地点：
重要承诺、秘密与冲突：
物品与归属：
身体 / 情绪 / 关系状态：
尚未解决的事件：
必须保持一致的称呼和事实：
```

总结应区分“实际发生”“角色相信”“用户要求未来发生”三种信息。导演指令不是已发生剧情。

## 状态账本

状态账本保存当前值，而不是重述整段剧情。可从以下字段中按故事需要选择：

```yaml
time: 当前日期和时间
location: 当前地点
present_characters: []
relationships: {}
physical_state: {}
clothing: {}
important_items: {}
open_events: []
```

不要为了完整而强制加入与题材无关的字段。角色专用状态栏应该针对故事设计。

## 聊天记录与风格锚点

TXT 导入的聊天记录代表已经发生的具体过程，不能替代角色卡和世界书。长篇续写时，应保留最近原文，并从早期历史中检索与当前场景有关的片段。

另选 3-8 段最能代表目标文风的角色回复作为风格锚点。它们应覆盖对话、动作、环境描写和情绪表达，但不要长到挤占主要剧情上下文。
