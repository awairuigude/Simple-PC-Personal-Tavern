# Simple PC Personal Tavern

一个以个人电脑、自用长篇中文角色扮演和旧对话迁移为目标的 SillyTavern 改造分支。

本仓库目前基于 [SillyTavern 1.18.0](https://github.com/SillyTavern/SillyTavern)。第一阶段已经完成 TXT 长对话导入：可以把普通文本聊天解析成 SillyTavern 的 JSONL 聊天记录，保留原文，并把文本中已有的阶段总结和累计总结写成 Qvink Memory 可读取的消息元数据。

这不是一个已经完成的全新酒馆，也不包含任何模型、API Key、私人聊天、角色卡或本机第三方插件。仓库会把已实现能力和后续计划分开说明，避免把路线图写成现成功能。

## 已实现：TXT 长对话导入

上游 SillyTavern 的聊天导入主要面向 JSON/JSONL。本分支在“聊天记录 -> 导入聊天”中增加 `.txt`，用于迁移从其他聊天网站、笔记或人工整理文档导出的长篇记录。

### 支持的编码

- UTF-8
- 带 BOM 的 UTF-8
- UTF-16 LE
- UTF-16 BE
- GB18030（包括常见 GBK 中文文本）

没有 BOM 且不是有效 UTF-8 的文件会按 GB18030 解码。

### 推荐格式

```text
用户：去车站。
林遥：收好地图，跟着你离开房间。

剧情总结：林遥与用户决定去车站，地图仍由林遥保管。

用户：继续。
林遥：两人抵达站台。

新通用总结：双方已经抵达站台；地图仍由林遥保管；车次尚未确认。
```

支持的用户标签包括 `用户`、`玩家`、`我`、`User`、`Human`、`Player`、`{{user}}` 以及当前 Persona 名称。支持的角色标签包括 `助手`、`角色`、`AI`、`Assistant`、`Character`、`{{char}}` 以及当前角色名。

标签后的冒号可用中文 `：` 或英文 `:`。正文可以跨多行，一直到下一个可识别标签。

可识别的总结标题包括：

- `剧情总结`
- `阶段总结`
- `故事总结`
- `对话总结`
- `新通用总结`
- `通用总结`
- `历史总结`
- `前情提要`
- `Plot Summary`
- `New General Summary`
- `General Summary`
- `Recap`

Markdown 标题和简单包裹也可以识别，例如 `## 剧情总结`、`【新通用总结】：...`、`**Plot Summary:** ...`。

### 导入规则

1. 有明确说话人标签时，每个标签块转换成一条用户或角色消息。
2. 没有任何说话人标签的纯文本不会被随意按段拆分，而是整体保留为一条角色消息。
3. 总结块不会伪装成普通聊天正文，而是附着到它之前的一条消息上。
4. 最后一份累计总结被标记为长期记忆基线；它之前的旧总结仍保存在文件中，但标记为不重复注入。
5. 累计总结之后的阶段总结保留为增量记忆。
6. 只有总结的 TXT 会自动创建一条承载记忆元数据的角色消息。
7. 每份导入聊天会记录解析器版本、消息数、总结数和识别到的总结标题，方便以后排查。

导入过程是本地确定性解析，不调用任何模型 API，因此不会因文本很长产生模型费用，也不会先把 1 MB 文本整份塞进上下文。

### Qvink Memory 的关系

导入器会生成 Qvink 使用的消息级 `qvink_memory` 元数据，同时保留一份 `txt_import.summaries` 结构化副本。这样已有总结可以直接成为长期记忆起点，不必立即花费一次 API 调用重写整份历史。

需要注意：

- Qvink Memory 本身是第三方扩展，位于本机用户数据/第三方扩展目录，受 `.gitignore` 保护，不随本仓库上传。
- 导入器记录了建议的 `recent_message_window: 16`，但“生成时保留最近多少条原文”最终由已安装的记忆扩展配置执行，不是 TXT 解析器单独完成的。
- 如果没有安装兼容的记忆扩展，聊天原文仍能正常导入和回看，但总结元数据不会自动参与模型提示词。
- 先用一小段样本检查角色与用户归属，再导入完整文件，尤其是来源网站使用自定义分隔符时。

更完整的操作步骤见 [docs/使用指南.md](docs/使用指南.md)。

## 为什么“有总结”仍不等于“完整接上长篇剧情”

只给模型一份 4,000 token 的总结，确实可能丢失原文的语气、铺垫、人物细节和具体动作。一个可持续的长篇记忆方案应同时使用几层信息：

```text
稳定设定：角色卡 + Persona + 世界书
长期事实：累计总结 + 状态账本
阶段发展：最近若干阶段总结
相关旧事：按当前场景检索出的历史原文片段
即时连续性：最近 20-40 轮原文
风格连续性：少量代表性原文 / 示例对话
```

当前提交先解决最底层的“把旧数据可靠迁入并保留”。最近原文窗口扩大、语义检索、风格锚点和状态账本仍在路线图中，不能仅靠这一次 TXT 导入自动获得。

## 多模型与“不失忆”

SillyTavern 把角色卡、世界书、聊天记录和大部分记忆数据保存在前端/服务端自己的数据层，而不是绑死在某一个模型中。因此可以在同一段聊天中切换 OpenAI 兼容接口、Claude、Gemini、本地模型等连接；模型切换不会删除聊天记录。

但“不删除记录”和“新模型理解完全一致”是两回事。不同模型有不同上下文长度、分词、提示词遵循能力和服务端内容政策。要把切换损失压低，后续需要统一的上下文组装器：无论正文模型是谁，都发送同一组角色设定、长期记忆、相关历史、近期原文和状态信息。

API Key、接口地址、模型预设和采样参数不会上传到本仓库。它们应在自己的 SillyTavern 连接面板中配置。

## 安装和启动

### 环境要求

- Windows、macOS 或 Linux
- [Node.js](https://nodejs.org/) 20 或更高版本
- npm（随 Node.js 安装）
- 至少一个可用模型来源：云 API、本地 OpenAI 兼容服务或 SillyTavern 支持的其他后端

### 安装

```powershell
git clone https://github.com/awairuigude/Simple-PC-Personal-Tavern.git
cd Simple-PC-Personal-Tavern
npm install
npm start
```

默认访问地址是 <http://127.0.0.1:8000>。首次启动会根据 `default/config.yaml` 创建本机 `config.yaml` 和用户数据目录。

Windows 也可以在安装依赖后使用仓库已有的 `Start.bat`。本机此前使用的便携 Node 启动脚本依赖仓库外的运行时目录，所以没有作为通用脚本上传。

### 只允许本机访问

上游默认 `listen: false`，只监听 localhost。个人使用时建议保持这个设置。不要直接把 8000 端口暴露到公网；需要从手机访问时，优先使用 Tailscale 等私有组网，并同时配置账户、密码和访问控制。

### 连接模型

启动后在 SillyTavern 的 API 连接面板中选择服务类型并填写接口。OpenAI 兼容中转、本地服务和官方 API 的地址/模型名各不相同，以对应服务文档为准。

`max_tokens` 或“最大输出”只是上限，不是模型每次必须写满的长度。回复提前结束可能来自自然收束、停止词、上下文预算、上游网关截断、超时或内容政策；只看“设置 4,000 但输出约 2,000”不能确定原因。

## 模型费用怎么计算

这个项目本身免费开源，不出售“电量”。真实费用来自所连接的模型服务，通常按输入 token 和输出 token 分别计费：

```text
单轮费用 = 输入 token / 1,000,000 * 输入单价
         + 输出 token / 1,000,000 * 输出单价
```

有缓存价的服务还要把输入拆成缓存命中与未命中两部分。最大输出上限不等于实际计费输出量。

与“电量站”比较时，应先换算：

```text
每电量价格 = 充值金额 / 获得电量
每轮平台成本 = 本轮消耗电量 * 每电量价格
```

再拿同一模型、相近输入长度和真实输出长度做比较。中转站可能包含服务费、免费额度或动态倍率，模型展示名也可能是服务商自定义别名，不能仅凭名称断定它等同于某个官方 API 型号。价格变化快，因此仓库不硬编码某天的模型报价。

## 创作控制与内容边界

角色卡、系统提示词、预设和世界书可以控制叙事视角、篇幅、节奏、是否替用户行动、是否强行升华、是否突然绝望转折等写作行为。这些属于“叙事控制”，适合做成可开关模块。

网上所谓“破甲”通常也是一组提示词或预设，不是一个能关闭模型服务端审核的技术开关。本地前端不能保证绕过云 API 的服务条款或安全策略；中转站即使表现更开放，也可能是使用了不同模型、不同上游、不同系统提示词或不同审核配置。

本项目可以面向成年人之间的虚构创作提供可配置、少打断的叙事体验，但不会把规避服务商审核写成保证，也不会把涉及未成年人的色情内容设计为功能目标。若用户需要更可控的模型行为，可以接入符合自己硬件条件的本地模型；本地部署不需要云端模型 Key，但仍需要下载模型、运行推理服务并自行承担数据、法律与设备安全责任。

## 人设和背景资料放在哪里

- **角色卡**：AI 扮演者的稳定身份、性格、语气、经历和开局。
- **Persona**：用户在故事中的身份和稳定资料。
- **世界书**：地点、组织、配角、制度、物品、术语等按关键词触发的资料。
- **作者注释**：当前章节的短期目标、氛围和镜头重点。
- **聊天记录**：已经发生的具体正文。
- **记忆 / 总结**：从大量历史中提炼的长期事实与阶段进展。
- **状态账本**：时间、地点、关系、物品、身体状态和未结事件等结构化当前值。

不要把全部信息塞进一条系统提示词。可直接参考 [docs/人设与背景模板.md](docs/人设与背景模板.md)。角色卡和世界书的来源包括自己编写、导入兼容 SillyTavern 的公开角色卡，以及在明确许可下改写公开模板；使用他人内容时应检查授权和隐私。

## 隐私与 Git 边界

本仓库沿用并加强了上游的数据忽略规则。以下内容不会作为本次提交上传：

- `data/` 和用户数据
- `secrets.json`、`.env`、`config.yaml`
- API Key 和连接设置
- 聊天记录、`*.jsonl`
- 角色卡、Persona、世界书
- Quick Replies、模型预设和本地设置
- 第三方扩展、插件、向量库、缓存和备份

不要为了“方便同步”强行提交这些被忽略目录。仓库是公开的；任何准备提交的新配置都应先检查是否包含真实 Key、私人对话或人物资料。

## 路线图

### 近期

- 为超长 TXT 增加导入预览、说话人映射和错误报告
- 支持更多常见网站的导出分隔格式
- 将近期原文窗口从固定建议值改为可配置的 20-40 轮策略
- 增加导入后统计页，显示消息、总结、疑似未识别标签和编码
- 补充真实浏览器端上传回归测试

### 长篇记忆

- 从历史原文中按当前人物、地点、物品和事件检索 6-12 个相关片段
- 使用累计总结、阶段总结、状态账本和近期原文分层组装上下文
- 保存代表性原文作为风格锚点，减少切换模型后的文风漂移
- 记忆 Agent 与正文 Agent 分离，允许便宜模型做提取和整理
- 记录每条记忆的来源消息，支持回溯、修正和冲突检测

### 模型与可靠性

- 多模型配置档和一键切换，保持统一记忆输入
- 正文、总结、状态更新使用不同模型
- 超时、限流和接口失败后的可见重试与备用路由
- 按真实 token、缓存命中和单价统计单轮成本
- 云端主模型与本地备用模型混合使用

### 叙事与状态

- 可开关的用户自主权、节奏、防抢话、防全知、防强制升华等模块
- 可审计的导演指令识别，不把“后续剧情”误记为已经发生
- 时间、地点、人物关系、物品和未结事件状态账本
- 世界线、存档点、分支和回滚
- 角色专用状态栏模板，而不是一套字段强塞所有故事
